# Apple Ads API research — 2026-10-27

Public documentation research only. This report contains no authenticated account data, keyword scores, campaigns, or advertising changes. Request examples are in `apple-ads-readonly-request-examples.json`; public-source hashes are in `apple-ads-official-sources.json`.

## Current API and authentication

Apple now documents **Apple Ads Platform API v1**, hosted at `https://api.ads.apple.com`. Do not confuse this with the older Campaign Management API hosted at `api.searchads.apple.com/api/v5`, or App Store Connect API. V1 scopes account operations using `X-AP-Context: adAccountId=…`. First call `GET /v1/me`, then `GET /v1/acls` (neither needs that context header); verify the selected account and its roles before scoped calls. The IDs must come from the response, not from a remembered organization ID. [Account access](https://developer.apple.com/documentation/apple-ads-platform-api/access-overview), [API calls](https://developer.apple.com/documentation/apple-ads-platform-api/calling-apple-ads-platform-api).

OAuth uses an Apple Ads API user's registered P-256 public key and corresponding private key. Its `clientId`, `teamId`, and `keyId` are Apple Ads credentials, not ASC issuer/key IDs. Sign an ES256 client-secret JWT with `iss=teamId`, `sub=clientId`, `aud=https://appleid.apple.com`, UTC `iat`, and an expiry below 180 days. Exchange it at `POST https://appleid.apple.com/auth/oauth2/token` with form fields `grant_type=client_credentials`, `client_id`, `client_secret`, `scope=searchadsorg`. Bearer tokens expire after 3600 seconds. Keep secrets in memory/protected files; don't put them in command-line arguments or receipts. [OAuth](https://developer.apple.com/documentation/apple-ads-platform-api/implementing-oauth-for-the-apple-ads-platform-api).

Apple's setup UI supports API Account Manager, API Account Read Only, Limited Access API Read & Write, and API Read Only. A user can have web access without an API role. Prefer existing API access; absence is a credential/setup blocker, not proof that keyword discovery is unsupported. Do not invite users or change permissions in a research-only lane. [API setup help](https://ads.apple.com/maps/apple-ads/help/campaigns/0022-use-apple-ads-platform-api).

## Actual keyword discovery capabilities

`POST /v1/suggestions/keywords/query` is a documented read-only discovery endpoint. It requires filters `promotedObjectId EQUALS ["6826601708"]` and `promotedObjectType EQUALS ["APPSTORE_APP"]`; optional `terms IN [...]` seeds ideas, and `countriesOrRegions IN ["US"]` scopes the market. It returns keyword `text` plus `popularity`; sort descending and paginate. Prefer one country per request when making cross-market ASO comparisons. [Keyword endpoint](https://developer.apple.com/documentation/apple-ads-platform-api/query-keyword-suggestions).

`popularity` is a **relative 0–100 score**, not monthly searches, organic ranking, conversion probability, or keyword difficulty. The suggestion endpoints are stateless; querying does not apply a recommendation or create a paid keyword. [Score object](https://developer.apple.com/documentation/apple-ads-platform-api/keywordsuggestion), [Suggestions overview](https://developer.apple.com/documentation/apple-ads-platform-api/suggestions-endpoints).

`POST /v1/suggestions/phrases/query` accepts `queryType EQUALS ["SEARCH"]` with `phrase IN ["photo counter", "拍照计数"]` for exact phrase lookup, or `phrase LIKE ["counter"]` for partial discovery. This route explicitly does **not** require `promotedObjectId`. The `SUGGESTION` route instead requires promoted-object filters. The endpoint's filter table does not list a country parameter, so do not invent one or label returned scores as country-specific. Its specific SEARCH-route rules override the more generic `RecommendationQueryRequest` text that says promoted-object filters are always required. [Phrase endpoint](https://developer.apple.com/documentation/apple-ads-platform-api/query-phrase-suggestions).

## Country and time-specific search popularity

`POST /v1/insights/apps/search-term-popularity/query` returns popular search terms by country and genre. Use `countryOrRegion`, `genre` (for this app, investigate `PRODUCTIVITY_UTILITIES`), and optionally `searchTerm` filters. Request `rankInGenre`, `searchPopularityInGenre`, `searchPopularity1to100`, and `searchPopularity1to5` in `fields`; preserve their names and scales. It uses a different filter schema from suggestions: a scalar for `EQUALS`, an array for `IN`. Limit sorting to two fields, page size to 10000, and follow pagination. A missing row isn't a measured zero. [Popularity endpoint](https://developer.apple.com/documentation/apple-ads-platform-api/query-app-search-term-popularity-data), [Request object](https://developer.apple.com/documentation/apple-ads-platform-api/searchtermpopularityqueryrequest).

Weekly windows are Sunday–Saturday, published Mondays at 07:00 UTC, retained for 65 weeks. Monthly data refreshes on the fifth UTC for the prior calendar month, retained for 15 months. On 2026-10-27, the completed week 2026-10-18 through 2026-10-24 is a sensible initial request; September is the latest completed published month. Save the requested period and returned date with each score. [Time range](https://developer.apple.com/documentation/apple-ads-platform-api/searchtermpopularitytimerange).

## App search and localization

`GET /v1/search/apps` supports `query`, `returnOwnedApps`, `cpids`, and repeated `storeFronts` parameters. Query needs at least three alphanumeric characters, or two for CJK. It searches app/developer names, so it is useful for name collision checks, not a promise of organic keyword ranking. `GET /v1/apps/{adamId}` returns app name, publisher, primary language/genres, and `availableStorefronts`. Catalog results can include public apps, whereas advertising creation requires ownership. [App search](https://developer.apple.com/documentation/apple-ads-platform-api/searches-for-a-list-of-apps), [Search overview](https://developer.apple.com/documentation/apple-ads-platform-api/search-apps-endpoints).

`POST /v1/metadata/apps/supported-languages/query` supports `countryCode IN ["US", "CN"]`. It returns advertising-supported/default language mappings, not the app's current ASC metadata or organic indexing rules. Keep US/en-US and CN/zh-Hans research separate; do not assume English US traffic equals Chinese demand. [Supported ad languages](https://developer.apple.com/documentation/apple-ads-platform-api/query-supported-app-languages).

## Interpretation and authorization boundaries

- Suggestions/popularity research uses documented GET and POST-query calls. It does not require creating, enabling, or paying for a campaign as part of the request schema. Actual availability still needs live account/authentication verification; do not promise that every account or unpublished app will succeed.
- Existing campaign search-term reports describe queries that triggered ads. Impression-share rank is an **advertising** comparison, not organic App Store rank. Avoid substituting those for the general country/genre popularity dataset. [Insights overview](https://developer.apple.com/documentation/apple-ads-platform-api/insights-endpoints).
- A `KEYWORD` enum in the recommendations model does not establish a keyword recommendation apply/query endpoint: the current recommendations API exposes daily-budget and Target CPA lifecycle endpoints, while keyword discovery is in suggestions. [Recommendation categories](https://developer.apple.com/documentation/apple-ads-platform-api/recommendationcategory).
- If live access fails, record the sanitized endpoint, status/error, and exact missing setup. Continue name/copy preparation from public Apple evidence, but label it as not yet backed by live Apple Ads scores. Do not silently use an undocumented UI endpoint and present it as official API data.
- App Store product-page names and keywords are changed through App Store Connect, not Apple Ads. ASO research authorizes neither advertising spend nor automatic release submission.
