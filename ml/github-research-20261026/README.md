# CountScope：GitHub 高星项目与下一轮训练研究

2026-10-26 查询官方 GitHub API，筛查 24 个仓库，按固定 commit 阅读相关训练、推理和损失代码。**优先建议沿用 Ultralytics，先验证完整切片输出与整图融合，再对齐训练尺度、加强旧小目标特征约束。SAM/Cellpose 用于离线实例标注与分割对照。** 本轮完成的是源码研究、已有数据诊断和合成兼容检查，没有新训练成绩，也没有升级原训练环境或替换 App 模型。

## 几个直接影响下一轮的源码发现

**1. 目前的四切片流程不等于完整 SAHI。** 官方 `get_sliced_prediction` 在 `perform_standard_pred=True` 且切片数大于 1 时添加整图预测，收集各切片输出再做合并；当前流程在合并前已经按象限中心丢弃了一批框，并且没有整图分支。旧缓存不含被丢弃的框，不能在旧缓存上换一个合并函数就声称复现 SAHI。`slice_coco` 还提供训练切片准备，默认保留负片；训练分组和采样权重要按原物理皿保持一致。[固定源码](https://github.com/obss/sahi/blob/b5a153ee7bcb1fd84a7b868575ff14131e7423ce/sahi/predict.py#L176)

SAHI 的默认 GREEDYNMM/IoS 不会在所有参数下原样执行：模型置信度阈值小于 0.1 时会切换到 NMS/IoU，除非设置 `force_postprocess_type=True`。我们的 AP 缓存用 0.001 阈值，因此实验必须记录实际走的分支。IoS/NMM 可能把两个真菌落并为一个，需用固定同图回归验证，不能当作确定改进。

**2. 官方特征蒸馏已经在本机可用，但不能直接当作旧方案的替代。** 本机 Ultralytics 8.4.123 接受 `distill_model`，默认是检测颈部多尺度特征的教师分数加权 L2 与投影层；我们之前是仅旧训练图上的类别 KL/DFL 输出约束。官方默认对整个 batch 蒸馏，可能把旧模型在新空皿上的误报也传给学生。即使教师/学生初始权重相同，随机投影层也会引入非零特征损失。[官方实现](https://github.com/ultralytics/ultralytics/blob/aa1f778a75a610f7dd2aa4762df1c25f6a3063d7/ultralytics/nn/distill_model.py)

本轮已用本地权重和合成数据验证 CPU 接口，以及 MPS 上 2×3×128×128 的前向/反向；学生和投影层梯度有限，教师保持 eval/frozen、无梯度且状态不变，优化器步数为 0。这只证明小规模算术/接线可用，不代表密集 1024 图训练、保存、导出或准确率通过，不能据此删除原密集目标 MPS 兼容处理。

**3. Cellpose 的默认过滤会丢掉我们的关键样本。** 当前源码 `min_train_masks=5` 会过滤空皿，也会过滤很多只有 2–4 个大菌落的裁剪样本。合成检查确认设为 0 后可以保留这些样本；空掩膜生成零 flow，单独分割损失在 CPU/MPS 上有限，背景 logit 梯度非零。完整网络/数据管线训练仍需另测。micro-SAM 默认交互训练也有最少实例筛选；自动实例 decoder-only 路径需要显式选择。[Cellpose 固定源码](https://github.com/MouseLand/cellpose/tree/a54cb48849b7e225a81e8e43dcb042d42427f543) · [分割研究与逐行证据](segmentation.json)

现有 59 个检测框不能直接当作 Cellpose、StarDist 或 micro-SAM 的实例掩膜，更不能把矩形填满当真值。应在训练组中用 SAM/micro-SAM 辅助出草稿，再逐实例修正。验证和 App 推理必须不依赖真值框或手动画区域。SAM3 的 box-only 检测/presence 配置也不等于获得了掩膜监督。

**4. 高星骨干与专用计数论文实现要分开看。** GroundingDINO 是 10,703 Star 的文本检测基础模型，但所查官方仓库的训练代码仍有 TODO；DINOv2/v3 是特征模型。CountGD、CountGD++、DAVE、LOCA 本次分别为 338、72、83、67 Star，属于值得研究的专项实现，不应包装成高星通用工具。[通用计数源码审查](general-counting.json)

CountGD++ 的正/负文本竞争可供离线“菌落 vs 反光/印字”教师实验借鉴，但权重与 CUDA 算子成本较高；源码 demo 也不等于论文完整增强流程。DAVE 零样本验证按簇频率保留主要簇，且超过 500 候选时跳过验证，可能不适合稀有形态和密集菌落。LOCA 训练中的密度归一化和对象数归一化需要零目标安全处理，不能直接把空皿加入原训练代码。

**5. P2 需要当作新架构实验。** 当前 YOLO11 输出 stride 8/16/32，源码虽有浅层 P2 张量，却不是检测输出。查到的官方 P2 配置是 YOLOv8/YOLO26，没有现成 YOLO11-P2 配置；三尺度教师也不能直接接四尺度学生。1024 输入的网格位置数会由 21,504 增至 87,040，但这只是网格数，不是测得的四倍运行时间或内存。它还会打破当前逐键、同形状权重融合的前提。

## 对我们已有数据的只读诊断

本轮读取已有训练/验证记录，未在这些真实图片上运行新的模型推理，也未读取旧 63 图或封存 36 图内容：

- 新增正例用于训练的实际是 **7 张、32 个目标**，缩至 1024 后短边中位数 **191 像素**；旧训练集为 **18.88 像素**，新正例验证集为 **58.09 像素**。新增训练目标全部属于大目标组，不能用这批数据单独代表小菌落与普通手机全图。
- 当前准备样本直接整体缩放训练，推理时每个 60% 尺寸切片又放大至 1024，忽略边界截断时目标会再放大约 **1.667 倍**。训练样本中的“整图”包含此前已裁剪的 ROI，不等于原始完整培养皿照片。
- 实际八轮增强后呈给损失的标注框累计：旧来源 253,310，新难例 2,777，既有临床来源 11,034。图片采样均衡不等于损失或梯度均衡；空皿零框也不代表没有背景分类损失。
- 仅做 GT 可见框的几何投影时，新训练目标中有 5/32 会在象限规则下保留多个投影。该检查不是模型推理，也没有模拟 NMS；它不能证明实际误差都由切片造成。旧小目标退步仍需要通过特征、置信度和后处理的独立对照定位。

## 下一轮建议执行顺序（尚未执行）

1. **冻结原模型，先做推理对照。** 在当前完整标注的 prepared 图片范围内保存整幅输入和所有切片原始框、来源与置信度，再预注册少量合并配置。明确低置信度分支、部分目标、负片、全图分支和最大检测数；保留原推理作为基线。这样先分清模型错误与丢框/去重问题。
2. **对齐训练尺度与实际场景。** 从训练组生成整幅输入和切片，保留旧小目标、真实反光空皿与大/相接目标。当前 7 张新增训练正例全部是 ROI 裁剪；恢复为原始全皿前必须补齐 ROI 外标注，或使用明确支持的 ignore/隔离策略，不能把未标注菌落当背景。所有派生视图仍归原物理组，显式处理截断目标，记录各来源/尺寸的实际 loss 和梯度贡献。不要把新验证组变成训练资料。
3. **单独比较特征保留方案。** 在相同切片输入上，仅对旧训练子集保护 P3 与小目标区域，检查教师质量、投影层初始目标和各层损失量级。做完整保存/重载检查后才启动有限训练；旧保护门槛保持不变。
4. **补掩膜、做自动分割对照。** 标注覆盖小/密集、大/相接、真实空皿的独立训练组。先测试 Cellpose 自动推理与空样本保留，再考虑微调或蒸馏给轻量模型。SAM 的框提示只用于训练标注辅助，不用于冒充自动验证。
5. **把真实背景误报单独建模。** 从训练图中挖掘反光、印字、凝露候选，人工复核后训练轻量候选验证器，DINO 特征可作离线参考。验证器可能误删真目标，仍须通过旧 FN/FP/计数门槛；它也不能代替正确去重。P2/RF-DETR 留作后续独立架构对照。

推理对照和方案选择仅使用训练/开发验证集。唯一候选冻结后再做旧 63 图回归，失败不据此更换候选；封存 36 图不参与调参。最终验收继续分别检查旧物种/尺寸、临床场景、困难正例和真实空皿。已有 4 张难例验证图过小且已用于多轮选择，不能宣称新的独立泛化成绩；需要新物理组和未参与调参的测试。任何开发改善都不等于 iPhone/CoreML 验收。
